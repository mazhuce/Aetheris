# H1-H7 后续交付规划

本轮已完成 H1-H7 的代码级止血并提交。后续工作以“可运行、可恢复、可观测、可发布”为验收顺序，不以新增页面或新增 CRUD 作为完成标准。

## 阶段一：运行时闭环（下一工作日）

1. 启动 Docker Compose，确认 11 个业务容器、Prometheus 均健康。
2. 从 Prometheus targets 页面确认 gateway 与 9 个服务为 `UP`，并验证 `http_server_requests_seconds`、JVM 与数据库连接池指标可见。
3. 执行一次 PostgreSQL 备份；创建一条可识别测试记录；在隔离卷中恢复并核对迁移版本、记录数和关键业务字段。
4. 以随机 JWT secret、内部 token 和管理员密码启动；验证弱默认值、空值和短值均阻止启动，合法随机值可启动。

验收证据：命令输出、备份文件校验和、恢复前后 SQL 对账、Prometheus target 截图或导出结果。

## 阶段二：H1-H7 生产化加固（2—3 个工作日）

- H1：为批量权限接口增加契约测试、1000 条上限测试、auth 不可用时的 503/fail-closed 测试；记录单次列表鉴权耗时和授权命中率。
- H2：对字段血缘查询执行 `EXPLAIN (ANALYZE, BUFFERS)`，确认 source 索引命中；补充有环图、深度上限和空结果测试。
- H3：为语义指标、版本快照增加分页游标或显式 page/size；将 500 条上限变成 API 契约，并增加慢查询指标。
- H4：增加“数据库写入成功但调度同步失败”的补偿任务/重试记录，避免事务外移后出现最终一致性盲区。
- H5：增加并发发布集成测试，确认同一 dashboard 不产生重复版本号，冲突返回可解释的 409。
- H6：将表达式校验升级为 AST/函数白名单；保留当前危险关键字与注释拦截作为第一层防线。
- H7：统一错误响应字段（requestId、code、message、timestamp），并覆盖网关过滤器、参数校验、下游超时和未知异常。

## 阶段三：发布与升级（3—5 个工作日）

1. 生成可复制的 `.env` 初始化向导，不在仓库或镜像中携带任何可上线密钥。
2. 固化镜像 tag、SBOM、漏洞扫描、Compose 配置检查和最小权限运行用户。
3. 提供一键安装、升级、回滚文档；升级前自动备份，迁移失败自动停止并保留现场。
4. 增加 smoke/e2e 流程：登录 → 元数据列表 → 权限拒绝 → 指标查询 → 看板发布 → 备份恢复。

## 阶段四：商业化最小闭环（随后一周）

优先交付“数据资产识别”最小可交付版本：数据源接入、元数据同步、字段血缘、质量概览、权限审计和可导出的资产报告。R1 实时湖仓继续保留 ADR 与技术验证，但不以扩展 Flink/Iceberg 面为现金流前置条件。

## 明确不纳入本阶段

暂不扩展 M5b 供应链细节、视觉翻新、`comingSoon` 占位页和大规模新 CRUD。任何新能力必须先通过运行时、恢复、授权、回归和发布五项门禁。

## 每次迭代的完成门禁

代码变更 → 定向测试 → 全量测试 → `git diff --check` → Compose 配置校验 → 运行时 smoke → 备份/恢复证据 → 独立 Git 提交。未完成运行时证据时，只能标记为“代码已实现”，不能宣称“生产可用”。
