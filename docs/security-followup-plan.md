# H1-H7 后续交付规划

本轮已完成 H1-H7 的代码级止血并完成受影响模块级验证。后续工作以“可运行、可恢复、可观测、可发布”为验收顺序，不以新增页面或新增 CRUD 作为完成标准。

## 阶段一：运行时闭环（下一工作日）

1. 启动 Docker Compose，确认 11 个业务容器、Prometheus 均健康。
2. 从 Prometheus targets 页面确认 gateway 与 9 个服务为 `UP`，并验证 `http_server_requests_seconds`、JVM 与数据库连接池指标可见。
3. 执行一次 PostgreSQL 备份；创建一条可识别测试记录；在隔离卷中恢复并核对迁移版本、记录数和关键业务字段。
4. 以随机 JWT secret、内部 token 和管理员密码启动；验证弱默认值、空值和短值均阻止启动，合法随机值可启动。

验收证据：命令输出、备份文件校验和、恢复前后 SQL 对账、Prometheus target 截图或导出结果。

## 阶段二：H1-H7 生产化加固（2—3 个工作日）

- H1：已增加批量权限 1000 条上限、auth 不可用时的 503/fail-closed 语义，以及单条/批量鉴权耗时、命中/拒绝/不可用计数；真实 HTTP 契约和 Prometheus 端点仍待运行时核对。
- H2：已补充有环图、深度上限和空结果测试；`EXPLAIN (ANALYZE, BUFFERS)` 的 source 索引实测仍待运行时环境。
- H3：已增加显式 `page/size`（size 1–500）并保留权限过滤顺序；查询审计已补充低基数计数器、慢查询计数器和 P50/P95 Timer，Prometheus 端点的运行时可见性仍待核对。
- H4：已增加 `scheduler_sync_outbox` 补偿记录、幂等领取、定期重试、最大尝试次数和孤儿 Quartz Job 清理；仍需在运行时故障注入环境验证恢复时延与多副本竞争。
- H5：已为 dashboard 发布保留行锁串行化、发布状态冲突检查和可解释的 409；serving 模块回归测试已覆盖冲突映射，真实双会话数据库竞争仍待运行时注入。
- H6：已将质量规则谓词校验升级为递归下降 AST 与函数白名单；自定义只读 SQL 增加函数调用白名单扫描，并保留危险关键字、注释和多语句拦截。
- H7：统一错误响应字段（requestId、code、message、timestamp），并覆盖网关过滤器、参数校验、下游超时和未知异常。

## 阶段三：发布与升级（3—5 个工作日）

1. 生成可复制的 `.env` 初始化向导，不在仓库或镜像中携带任何可上线密钥。
2. 固化镜像 tag、SBOM、漏洞扫描、Compose 配置检查和最小权限运行用户。
3. 提供一键安装、升级、回滚文档；升级前自动备份，迁移失败自动停止并保留现场。
4. 增加 smoke/e2e 流程：登录 → 元数据列表 → 权限拒绝 → 指标查询 → API key 申请/审批/轮换/撤销 → 调用账本统计 → SLA 评估 → 看板发布 → 备份恢复。

## 阶段四：商业化最小闭环（随后一周）

优先交付“数据资产识别”最小可交付版本：数据源接入、元数据同步、字段血缘、质量概览、权限审计和可导出的资产报告。本轮已把 API 资产从登记台账推进到 metric/table 受控执行契约，并完成 API key 申请/审批、摘要存储、轮换/撤销、持久化分钟配额、跨副本固定窗口限流、调用账本统计和 SLA 错误预算评估；后续继续补告警联动与服务级治理。R1 实时湖仓继续保留 ADR 与技术验证，但不以扩展 Flink/Iceberg 面为现金流前置条件。

## 明确不纳入本阶段

暂不扩展 M5b 供应链细节、视觉翻新、`comingSoon` 占位页和大规模新 CRUD。任何新能力必须先通过运行时、恢复、授权、回归和发布五项门禁。

## 每次迭代的完成门禁

代码变更 → 定向测试 → 全量测试 → `git diff --check` → Compose 配置校验 → 运行时 smoke → 备份/恢复证据 → 独立 Git 提交。未完成运行时证据时，只能标记为“代码已实现”，不能宣称“生产可用”。
