# 产品能力路线图

> 更新基线：2026-09-10。状态以真实代码、测试和容器验收为准，不以菜单或静态页面是否存在作为完成依据。

## 成熟度定义

| 等级 | 定义 | 进入产品导航的条件 |
| --- | --- | --- |
| 规划 | 只有需求或占位设计 | 不进入导航 |
| 可用 | 前后端链路可运行，具备基础权限、异常反馈和持久化 | 可以进入导航 |
| 完整 | 生命周期闭环、跨服务消费、迁移与自动化测试齐备 | 正式能力 |
| 企业级 | 审批、细粒度权限、可观测、容量与灾备经过生产验证 | 企业生产就绪 |

“页面可点击”不等于“能力完成”。新能力至少要同时满足：真实数据、后端校验、角色边界、失败反馈、数据库迁移、自动化回归和 Docker 升级验证。

## Spark SQL M0：恢复与可信状态（已完成）

现有 Spark Thrift SQL 链路已恢复并通过真实平台身份的容器路径验收：两个 Spark 数据源的 relay 地址已同步，`SELECT 1`、专用小库的 schema/table/column 读取和已知 3 行数据检查通过。连接配置的 `active` 与真实探测健康已分离；列表不会自动触发 JDBC，探测有超时、并发上限、过期降级、脱敏错误和配置版本 fencing。恢复脚本会检查现有 Derby/HDFS 存储，拒绝替代初始化；专用 fixture 与重复运行脚本已纳入 CI 合同测试。

隔离写入、授权撤销和同分区幂等重跑已经纳入专项验收；权限目录遗漏 `datasource.query` 与 PostgreSQL JSONB 授权字段绑定问题已通过增量迁移和类型处理器修复。M0 继续只证明 Spark SQL 数据通路，独立 Spark 应用由后续受管计算里程碑负责。

## 受管计算 M1–M3：可靠执行与混合流水线（已完成）

| 里程碑 | 已交付能力 | 安全与恢复边界 |
| --- | --- | --- |
| M1 可靠任务执行 | 不可变执行快照、attempt/event 审计、租约、心跳、fencing token、超时与受控重试 | 进程失联不会永久占用活动实例；重试复用已固化定义，不读取漂移后的在线配置 |
| M2 受管 Spark | 固定环境与资源上限、白名单 PySpark 制品、SHA-256 校验、制作者/复核者分离、application ID、增量日志和远端确认取消 | `unknown` 与普通失败严格分离，结果未核对时禁止自动或人工重复提交 |
| M3 混合流水线 | SQL / Spark /质量 DAG、提交前闭包校验、质量豁免、对象级可见性、可靠取消、失败节点断点续跑 | 豁免只影响流水线上下游门禁；续跑只接受失败或已确认取消节点，并记录来源运行和续跑起点 |

M3 断点续跑会基于当前依赖图重新计算受影响的下游分支，不重复执行无关的成功分支；创建新运行前再次检查任务启用状态、节点类型与上游成功/有效豁免。排队任务可以直接取消；运行中的任务只有在 Spark 远端终止可确认时才完成取消，SQL/质量节点不会伪造取消成功。对于已取得受管句柄的 `unknown` Spark 节点，后台对账确认成功后会自动恢复原流水线的下游节点；确认失败或取消后才转为可人工断点续跑的终态。无受管句柄的 `unknown` Spark 执行可由管理员依据 application ID、外部日志或工单显式认领最终结果；服务端锁定精确 active attempt、拒绝覆盖可自动对账的执行，并写入不可修改、不可删除的核对记录，关联流水线继续复用同一自动恢复路径。

## 阶段一：企业语义层闭环（已完成）

### 1. 统一语义资产

- 正式业务域成为表、逻辑模型、语义维度和指标共同引用的稳定边界，不再依赖自由文本。
- 逻辑模型使用结构化实体图：实体、角色、真实表绑定、关系基数和等值关联表达式均可校验。
- 语义维度绑定受管数据表的真实字段，并区分枚举、时间和地理维度。
- 指标绑定业务域、逻辑模型、来源表、聚合方式、度量字段、结构化过滤、时间字段和可用维度。

### 2. 发布生命周期

```text
首次草稿 ──校验/试算──▶ 发布 v1 ──创建新版本──▶ v1 在线 + v2 草稿
   │                         │                         ├──发布──▶ v2 在线
   └──可删除                 └──可下线                 └──放弃──▶ 恢复 v1
```

- 编码是稳定身份，创建后不可修改。
- 发布必须通过真实表、真实字段、模型关系、业务域状态和查询口径校验。
- 每次发布生成不可变快照；线上版本和下一版草稿并行，编辑草稿不会中断现有消费者。
- 支持版本历史、放弃草稿、替换发布和下线；有发布历史的对象不允许物理删除。
- 停用业务域不影响既有线上查询，但禁止在该域发布新语义版本。

### 3. 统一消费

| 消费方 | 接入方式 |
| --- | --- |
| 指标资产 | 只展示当前在线的正式指标快照 |
| 分析数据集 | 可选择只读 SQL 或已发布语义指标；看板继续消费同一数据集协议 |
| 智能问数 | 优先检索并查询已发布指标，无匹配口径时才回退到元数据检索与只读 SQL |
| 外部/内部调用 | 只提交指标编码、维度、时间粒度和日期范围，不提交底层任意 SQL |

### 4. 查询安全边界

- 当前指标执行器只编译受控的 `SUM / COUNT / COUNT_DISTINCT / AVG / MIN / MAX`。
- 标识符必须来自已采集的真实表结构；过滤操作符和值数量均有白名单与上限。
- 日期格式、时间粒度、维度数量和返回行数都由服务端限制，返回最多 100 行。
- SQL 字面量转义、数据库方言时间分桶和只读数据源连接均在元数据服务内统一处理。

## 已知边界

- 当前语义指标以单个受管物理表为执行边界；逻辑模型中的多表关系用于建模和校验，尚未自动生成跨表 JOIN。
- `atomic / derived / composite` 已建立资产分层，但派生与复合指标目前仍使用同一受控聚合执行器，尚无指标表达式 DAG。
- 发布审批已实现制作者/复核者分离；审批列表与发布窗口已纳入 metadata 服务，跨服务审批委派和通知仍待后续增强。
- 断点续跑不允许跳过 `unknown` 节点；有受管句柄的 Spark 执行必须自动对账，无句柄执行允许管理员基于外部证据显式认领并留下不可变审计。外部状态持续不可达且仍保有受管句柄时不会开放人工覆盖。
- Docker Compose 是当前交付环境；Kubernetes、多副本容量与灾备尚未宣称完成。
