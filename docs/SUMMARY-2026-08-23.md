# Aetheris 数据平台 · 今日总结报告（2026-08-23）

> 本文面向完全没看过本项目的人，从头介绍项目是什么、今天做了什么、当前状态，以及后续计划。

## 1. 项目是什么

Aetheris 是一个**个人数据中台**，目标是通过持续迭代与功能拓展，逐步演进为**企业级数据平台**。

核心愿景：统一数据的「接入 → 元数据 → 质量 → 治理 → 服务开放 → AI/Agent」全链路，后端采用 Java 微服务架构，前端为 Web 控制台。

## 2. 总体架构与目录结构

采用 **Monorepo（单体仓库）**，顶层按「物理分层」组织，业务域下沉到 `services/`：

```text
aetheris/
├── apps/                    # 可运行应用
│   ├── web/                 # 前端控制台（React + Ant Design）
│   └── gateway/             # API 网关（Spring Cloud Gateway）
├── services/                # 后端微服务（按业务域划分）
│   ├── system/              # 系统管理（已实现）
│   ├── metadata/            # 元数据/数据源（已实现）
│   ├── auth/ ingestion/ quality/ governance/ serving/ workflow/ ai-agent/  # 规划中
├── packages/                # 跨模块/跨语言复用
│   ├── java/ web/ contracts/  # contracts 用于 OpenAPI/Protobuf
├── infrastructure/          # docker / k8s / terraform
├── database/                # 全局 SQL 参考
├── docs/ scripts/ tests/ configs/ examples/ tools/
├── .github/workflows/       # CI
├── docker-compose.yml       # 一键编排
├── Makefile                 # 常用命令入口
└── README.md
```

## 3. 技术栈与版本矩阵

| 层 | 选型 |
| --- | --- |
| 后端 | Java 21 LTS + Spring Boot 3.3.5 + Spring Cloud 2023.0.3 |
| 持久层 | MyBatis-Plus 3.5.7 + Flyway + PostgreSQL 16 |
| 前端 | React 18 + Ant Design 5 + Vite 6 + TypeScript 5.7 |
| 构建/部署 | Maven 3.9 + Docker Compose |

设计决策：Nacos 注册中心刻意延后到 Phase 2，避免骨架期引入版本矩阵风险；每个微服务使用独立数据库 schema 隔离。

## 4. 今天完成的每一步

### Step 1 — 目录架构评审与建立

评审了最初的目录草案，发现三类问题并修正：顶层混用「物理分层」与「业务域」、`services/` 缺少领域划分、缺少跨语言契约目录。落地了最终的 Monorepo 结构，并创建了 `.gitkeep` 占位文件让 Git 能跟踪空目录。

### Step 2 — Git 基线与工程规范

创建 `.gitignore`、`.editorconfig`、`.gitattributes`、`README.md`、`docs/architecture.md`、`docs/git-workflow.md`、`Makefile`、`CHANGELOG.md`、CI 占位工作流。初始化 Git 仓库（处理了沙箱对 `.git` 的写入限制与目录归属问题）。用户完成第一次提交「初始化」。

### Step 3 — 版本矩阵锁定

锁定 Java 21、Spring Boot 3.3.5、Spring Cloud 2023.0.3、MyBatis-Plus 3.5.7、PostgreSQL 16、React 18 等稳定兼容版本，并写入架构文档。

### Step 4 — 端到端最小闭环

搭建三个可运行工程并串起来：
- `services/system`：Spring Boot + MyBatis-Plus + Flyway，提供 `/api/system/ping` 与 `/api/system/configs`。
- `apps/gateway`：Spring Cloud Gateway，路由 `/api/system/**`。
- `apps/web`：前端控制台（初期为 Vue 实现，后重构）。
- `docker-compose.yml`：编排 postgres + system + gateway + web。

### Step 5 — 前端重构为 React + Ant Design

初期 Vue 前端是深色渐变玻璃拟态风格，被反馈「AI 味太重」。重构为 **React 18 + Ant Design 5** 的克制企业级控制台：浅色中性底、白卡片、细边框、单一蓝色主色、左侧导航 + 顶部栏 + 内容区、信息密度优先。设计规范写入 `docs/frontend-style.md`。

### Step 6 — 后端编译与运行时联调

用阿里云 Maven 源编译 system 与 gateway。联调时发现宿主机已有原生 PostgreSQL 18 占用 5432 端口，于是将项目数据库映射改为 **5433**，并让本地默认连 `127.0.0.1:5433`。

### Step 7 — Docker 一键构建打通

Docker Hub 在该网络环境走 IPv6 超时，Maven Central / npmjs 也不可达。解决：Dockerfile 基础镜像用 `docker.1panel.live/library/` 前缀，Maven 用阿里云源，npm 用 npmmirror。`docker compose build` 三个镜像全部构建成功，并完成纯 Docker 整栈启动验证。

### Step 8 — 元数据服务（数据源管理）

新增 `services/metadata` 微服务：数据源 CRUD（`/api/metadata/datasources`），网关加路由，docker-compose 加服务。踩坑并解决：多服务共用数据库时 Flyway 历史表冲突，最终采用**每服务独立 schema**（metadata 用 `metadata` schema）。

### Step 9 — 前端数据源管理页面

前端新增「数据源管理」页面：表格 + 新增表单，串起 `/api/metadata/datasources`，成为第一个前后端打通的完整业务功能。并做了端到端验证（新增一条数据源返回 id=3）。

### Step 10 — 整套代码审查与修复

审查后修复：文档补齐（README/架构/CHANGELOG）、补 `.env.example`、统一每服务独立 schema（system 迁到 `system` schema）、前端按路由分包、网关显式 CORS、CI 改为真实构建、Makefile 补齐命令、compose 增加 restart 策略与变量化口令。
