# Aetheris 当前功能支持报告

## 一、结论摘要

Aetheris 当前已经是一个**可运行的批处理型数据平台控制面**，核心闭环包括：

- 数据源接入、连接探测、元数据采集和安全查询；
- 批量数据同步、SQL 任务、Quartz 调度、依赖编排和执行记录；
- 数据质量规则、质量结果、趋势和问题待办；
- 数仓分层、血缘、业务域、逻辑模型、维度和指标语义层；
- 数据集、基础数据看板、查询历史和查询审计；
- 基于 DeepSeek 的数据助手 / NL2SQL，只读查询安全边界；
- JWT、RBAC、资源授权、数据范围、审计和系统管理。

但当前**不能按企业 GA 或完整实时数据平台对外承诺**。主要限制是：实时 CDC/流任务仍需按环境重新验收，指标暂不自动生成跨表 JOIN，多个数据源仍是查询型接入，Git 不自动部署，复杂看板能力、Agent 评测与引用、外部身份集成、Kubernetes/灾备/容量基准尚未完成。

## 二、功能支持矩阵

| 功能域 | 当前状态 | 当前支持内容 | 主要边界 |
|---|---|---|---|
| 登录与账号 | **支持** | 用户名密码登录、JWT、刷新/退出、密码修改、登录失败锁定、用户管理 | 尚未形成 OIDC / SAML / LDAP 等企业身份集成 |
| 权限与安全 | **支持基础闭环** | admin/viewer、角色、权限目录、用户组、组织、项目空间、资源授权、数据范围、权限版本、失败关闭、权限审计 | 全平台生产级多租户隔离仍需专项验证；前端按钮不代表后端授权已在所有新链路完成验收 |
| 数据源管理 | **支持** | 数据源增删改查、目录校验、连接测试、健康状态、凭据加密、JDBC URL 安全校验 | 不同引擎不保证方言完全统一；外部环境型数据源需要现场实例才能验收 |
| 元数据 | **支持** | 库/表/字段采集、注释、分层、业务域、stale 标记、表浏览和预览 | 不是自动理解所有数据库语义的统一目录 |
| 数据接入 | **支持批量接入** | PostgreSQL/MySQL 兼容源的批量 transfer，append/replace、批处理、事务回滚、并发互斥、运行记录和重放 | 不支持通用断点续传；非 PostgreSQL/MySQL 兼容目标不承诺批量写入 |
| SQL 开发与任务 | **支持** | 只读即席查询；SQL 任务保存时校验、运行、日志、重跑、业务日期占位符、依赖拓扑、持久化 Quartz 调度、幂等 | 写入只允许受控 INSERT/CTAS 类语句；不支持任意 DDL、多语句或危险操作 |
| 受管 Spark | **部分支持** | PySpark/JAR 制品、SHA-256、审批/复核、Runner、资源队列、日志、执行状态、未知结果核对、混合流水线、Git commit/blob/签名证据 | JAR 必须外部编译；Git 不自动部署或自动触发发布；持续负载容量和客户集群验收未完成 |
| Flink / CDC | **部分支持** | Flink SQL Gateway 任务、checkpoint/savepoint、暂停/恢复/升级/停止、失联状态和事件时间质量控制面；PostgreSQL/MySQL 为首批 CDC 源 | 不是所有数据源的通用流式接入；当前工作树需重新完成真实 CDC、重启恢复、HA 和 soak 验收 |
| 湖仓控制面 | **部分支持** | Iceberg 表/namespace、快照、branch/tag、schema change、maintenance 请求、质量观测和 Gold 门禁 | 依赖独立 Runner、REST Catalog、对象存储及锁定制品；当前发布不能仅凭历史报告宣称通过 |
| 语义建模 | **支持完整闭环** | 业务域、逻辑模型、实体/关系、语义维度、指标、真实表字段绑定、校验、草稿、评审、审批、发布、版本快照、回退和下线 | 指标执行边界为单个物理来源表；派生/复合指标尚无表达式 DAG |
| 数据治理 | **支持基础能力** | 表级/字段级血缘、SQL 血缘解析、影响分析、语义依赖图、数据标准、分类分级、治理问题 | 下线前跨资产自动阻断、策略自动执行、责任工单仍不完整 |
| 数据质量 | **支持** | 非空、范围、枚举、重复、自定义只读 SQL、AST/函数白名单、定时检查、结果留痕、趋势、隔离/释放和失败待办 | 复杂流式质量、长期质量基线和企业级质量运营仍需完善 |
| 数据集与看板 | **支持基础分析闭环** | SQL/语义指标数据集、草稿、发布、版本化看板、预览、基础图表和查询复用 | 暂不完整支持全局筛选联动、下钻、同比环比、分享、导出、订阅和高并发缓存 |
| 智能问数 | **支持受控问数** | 会话持久化、按用户隔离、指标优先检索；无指标时检索表/字段后生成只读 SQL；DeepSeek 故障分类和用户限流 | 暂无完整权限感知检索、逐项引用、评测集、成本观测、模型版本治理和高风险自主操作 |
| 数据服务 | **部分支持** | 订阅、服务授权、版本化指标/只读 SQL/表字段查询、API 资产基础生命周期、受控查询和审计 | 完整 API 资产到执行端映射、密钥/配额/分布式限流/SLA/服务市场仍需验收或补齐 |
| 运维与系统 | **支持基础运维** | 全服务健康、任务监控、告警中心、待办、审计日志、系统配置、发布/验收状态页 | 缺统一日志中心、资源监控、完整 trace/SLO、成本核算和客户级运维手册 |
| 部署交付 | **开发/测试环境支持** | Docker Compose、PostgreSQL、Flyway、多服务构建和本地验收脚本 | 尚未完成 Kubernetes/Helm、离线安装、N-1 升级回滚、生产 HA、PITR/灾备和正式容量承诺 |

## 三、数据源支持范围

“支持”分为三层：连接探测、元数据/查询、写入/接入。不是所有类型都具备三层能力。

| 数据源 | 探测 / 元数据 / 查询 | SQL 任务写入 | 批量 transfer |
|---|---:|---:|---:|
| PostgreSQL、TimescaleDB | 支持 | 支持 | 支持 |
| Greenplum、openGauss、CockroachDB、YugabyteDB | 支持 | 按 PostgreSQL 兼容性验证 | 按 PostgreSQL 兼容性验证 |
| MySQL、MariaDB | 支持 | 支持 | 支持 |
| TiDB、OceanBase | 支持 | 按 MySQL 兼容性验证 | 按 MySQL 兼容性验证 |
| Apache Doris、StarRocks | 支持 | 按 MySQL 协议和方言验证 | 按 MySQL 兼容性验证 |
| Apache Hive、Spark Thrift Server | 支持 | 支持 Hive/Spark SQL 写入 | 不作为通用 transfer 目标承诺 |
| SQL Server、Oracle、ClickHouse、Trino、SQLite | 支持 | **暂不开放统一写入** | **不支持通用 transfer** |

流式 CDC 当前以 PostgreSQL 和 MySQL 为首批范围；不应理解为所有数据源都已支持 CDC。SQL Server、Oracle、Hive/Spark 等外部环境型连接虽然已有目录和 JDBC 适配，但没有本地夹具时不能写成本机运行通过。

## 四、明确不支持或暂不承诺的能力

### 当前明确不支持

1. **语义指标自动跨表 JOIN**：逻辑模型中的关系用于建模和校验，不会自动编译成跨表查询。
2. **任意 SQL 写入和 DDL**：禁止多语句、DROP、TRUNCATE、ALTER、GRANT、可读取服务器文件的危险函数等。
3. **Git 自动部署**：平台可以固定 commit、读取 blob、校验签名并绑定 Runner 制品，但不会从 Git 自动部署或自动发布。
4. **完整复合指标计算 DAG**：`derived` / `composite` 已有资产分类，当前仍使用受控聚合执行器。
5. **所有数据源的统一写入与统一方言转换**：查询能力不等于写入能力。
6. **AI 自动执行高风险动作**：不允许智能体自主删表、授权、发布、生产重跑或 Schema 变更。

### 尚未达到企业交付标准

1. 通用实时采集、完整 CDC 运行态、Schema 演进审批、长期流任务恢复和容量 soak。
2. 看板全局筛选、联动、钻取、导出、订阅、阈值告警和大规模查询优化。
3. Agent 的权限感知检索、数字引用、固定评测集、提示词/模型版本发布和成本预算。
4. OIDC/SAML/LDAP、完整租户隔离、动态脱敏、KMS/证书轮换等企业身份与数据安全能力。
5. Kubernetes/Helm、滚动升级、失败回滚、离线包、PostgreSQL PITR、灾备演练和明确 RTO/RPO。
6. 统一日志、分布式 tracing、资源水位、SLO/错误预算、租户配额和成本核算。

## 五、当前成熟度判断

| 结论 | 判断 |
|---|---|
| 适合 | 本地部署、技术展示、批处理数据开发、数据治理和受控问数试用 |
| 谨慎适合 | 有明确数据源和运维人员的受控内部试点；需先完成对应环境的运行验收 |
| 暂不适合 | 直接作为多租户 SaaS、全量实时数仓、关键生产系统或承诺企业 GA 的交付物 |

## 六、建议的下一步验收顺序

1. 在当前提交冻结后重新执行后端测试、前端 type-check/test/build 和数据库迁移验证。
2. 重新执行数据源运行验收、R1–R5、Flink CDC/重启/事件时间及 Spark Runner 验收，不沿用旧报告的 `passed`。
3. 优先补齐统一权限贯穿、执行未知状态对账、备份恢复和升级回滚，而不是继续增加占位页面。
4. 再补看板交互/导出订阅、Agent 引用与评测、API key/配额/SLA，最后进行容量和客户环境试点。
