# Aetheris 主要问题 1–9 修复说明

日期：2026-09-08
范围：本机开发与验收部署、Docker Compose、WSL HDFS/Hive/Spark 链路、服务间身份与网关状态。
结论：审查列出的 1–9 项主要问题已按最小改动完成修复并部署到当前运行环境。13 个 Compose 容器全部健康，登录、令牌撤销、真实 Spark SQL、服务间身份校验和 OpenAPI 关闭均已通过运行态验证。

| 编号 | 原问题 | 本次处理 | 当前结果 |

## 关键实现

### 数据库与端口边界

- `docker-compose.yml` 将 Web、Gateway、PostgreSQL 的宿主端口分别限制为 `127.0.0.1:5173`、`127.0.0.1:8080`、`127.0.0.1:5433`。
- Redis 以及所有业务服务只在 Compose 网络内开放。
- PostgreSQL 当前初始化角色仍为超级用户，这是单机原型的既有结构；本次已经消除默认口令和局域网暴露。生产部署还应拆分每个服务的数据库账号和 schema 权限。

### WSL 数据栈边界

- `scripts/wsl-hive-test-server.sh` 使用运行时配置启动现有 HDFS、Hive Metastore 和 Spark Thrift，不格式化或清理既有存储。
- HDFS RPC、NameNode Web、DataNode 和 Spark Thrift 绑定 `127.0.0.1`。
- WSL relay 只绑定 WSL 专用 IPv4；Windows relay 只绑定 Windows 的 WSL 专用 IPv4，并拒绝 `0.0.0.0`/`::`。
- 当前 Hive 3 不支持 Hive 4 才提供的 `hive.metastore.thrift.bind.host`，因此使用 systemd 管理的 iptables 规则拒绝所有非 loopback 的 9083 入站连接。

### 服务身份边界

- Gateway 继续覆盖客户端传入的身份头，并为内部请求签发 `X-Aetheris-Identity` HMAC 身份。
- Workflow、Quality、Ingestion、Governance 现在验证签名、时间和身份内容，不再把 `X-User-Name` 或 `X-User-Role` 当作可信来源。
- 管理操作向 Auth 的内部授权接口做实时决策；Auth 不可用或响应异常时拒绝操作。

### 容器与镜像

- 当前应用镜像均为 `aetheris-local/<service>:security-20260908`。
- Java 和 Web 容器采用非 root 用户；应用容器使用只读根文件系统，只给 `/tmp` 等运行目录临时写权限。
- CI 配置已经加入扫描、SBOM、provenance 和签名，但这些远端工作流需要在代码推送后由 CI 实际运行；本地构建不能等同于已经发布并签名的制品。

### 网关共享状态

- `TokenRevocationStore` 在运行环境使用 Redis 保存撤销状态。
- `WriteRateLimitFilter` 使用 Redis Lua 脚本完成原子计数和过期设置。
- Redis 故障时安全相关请求返回 503，避免撤销和限流失效后继续放行。

## 仍需在生产化阶段继续做的工作

本次按“最小改动”封住了当前可直接利用的主要入口，但本机原型仍不等于可直接对公网开放的生产平台。后续生产化阶段应继续完成：

1. 为各服务拆分 PostgreSQL 账号，按 schema 授予最小权限，移除应用对超级用户的依赖。
2. 将基础镜像、PostgreSQL 和 Redis 也固定到审核过的 digest，并在远端 CI 实际产出、扫描和签名制品。
3. 用正式的秘密管理系统代替本机 `.env`，建立轮换和审计流程。
4. 企业环境为 Spark/Hive/HDFS 使用 Kerberos、受控代理或 mTLS；当前 firewall/relay 方案只面向本机开发验收。
5. 进入原计划的执行 attempt、lease/fencing、取消与失联恢复、独立 Spark 作业提交和 application ID 管理。
