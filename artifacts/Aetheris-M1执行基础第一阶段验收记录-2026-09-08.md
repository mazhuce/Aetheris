# Aetheris M1 执行基础第一阶段验收记录

日期：2026-09-08

## 本轮范围

本轮只建立现有 SQL 工作流的执行安全基础，不提交独立 PySpark/JAR 作业，也不声称已经具备完整的 Spark 批作业控制面。

完成内容：

- 保留 `(task_id, biz_date)` 唯一的逻辑实例，新增 append-only `execution_attempt` 保存每次物理执行。
- 数据库使用单条条件 upsert 原子抢占逻辑实例，并在同一事务创建 attempt、绑定 active attempt。
- 每次抢占递增 fencing token；结束状态必须同时匹配 instance、active attempt 和 fencing token。
- 内部重试也创建独立 attempt，失败记录不会再被下一次重试覆盖。
- attempt 保存任务名称、SQL、数据源、任务更新时间、定义 SHA-256、参数 JSON 和参数 SHA-256。
- 增加 worker、heartbeat、lease、remote handle、Spark application ID、artifact digest 等后续适配器字段。
- 租约过期自动转为 `unknown`，不把网络失联推断成确定失败，也不盲目重提。
- 日志关联 attempt ID；新增 attempt 查询 API，并在任务详情页显示 attempt 历史。

## 状态语义

逻辑实例继续兼容现有页面的 `success`、`failed`、`skipped`，同时加入 `submitting`、`cancel_requested`、`cancelled`、`timed_out`、`unknown`。

物理 attempt 使用 `queued`、`submitting`、`running`、`cancel_requested`、`cancelled`、`succeeded`、`failed`、`timed_out`、`unknown`、`skipped`。当前同步 SQL 路径实际使用 `running` 及相应终态；其余状态为下一阶段 ExecutionAdapter 预留，但数据库约束已经固定其含义。

## 迁移与恢复

V4 为兼容升级：新增表与列，保留原逻辑实例和日志数据。迁移时若发现旧版本遗留的 `running` 行，会标记为 `unknown` 并要求人工核对，不推断成功或失败。

回退应用版本时不要删除 V4 表或列；旧代码可以忽略新增列。需要恢复数据库时应使用迁移前备份或经过验证的前向修复迁移，不能把 Git 回退当作数据库回滚。

## 明确未完成

- 当前 SQL 调用仍是同步 HTTP/JDBC，尚无远端受管句柄。
- 尚未实现可验证的远端取消；因此页面没有提供只改本地状态的伪取消按钮。
- 尚未实现 ExecutionAdapter 的 submit/status/logs/cancel/reconcile 全契约。
- 尚未提交独立 PySpark/JAR 制品，也没有 Spark application ID。
- 租约长度覆盖 SQL timeout 与安全余量；同步 JDBC 执行期间尚未单独续租。下一阶段异步适配器必须增加 heartbeat。
