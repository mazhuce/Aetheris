# Aetheris：Spark 链路现状与后续详细迭代计划

检查日期：2026-09-07，Asia/Shanghai。代码基线：`37f6fc5`，本地 main 与本地 origin/main 引用一致；未重新拉取远端。

本报告基于源码、现有测试、部署脚本、运行中的 Docker/WSL 状态和数据库只读统计。没有重启服务、运行加工任务、修改业务代码、改动凭据、提交或推送 Git。本文是后续实施计划，不表示计划内容已经实现。

## 1. 核心结论

**Spark SQL 数据源接入和 SQL 加工路径已有实现；独立 Spark 作业管理尚未完成；当前 WSL Spark SQL 服务也没有运行，现有连接链路处于中断状态。**

不能用“支持 spark 类型”“有 Spark 相关提交”或“平台容器全部 healthy”代替整条链路验收。

## 2. 总体实施顺序

恢复已有 Spark SQL → 修复安全与执行一致性 → 交付独立 Spark 批作业 → 补齐治理和可靠流水线 → 开放受管数据服务 → 增强语义与智能问数 → 按需求扩大规模和流式能力。

Spark 不必等待数据服务市场或 Kubernetes 全部建设完成，但不能跳过执行身份、任务抢占、制品安全和失败语义。

以下使用 M0–M6，避免与原 roadmap 的阶段零到四混淆。每个里程碑验收后，再更新原路线图的真实成熟度；不提前把基础版本标成企业级。

## 3. M0：恢复并验收现有 Spark SQL 链路

### 目标

先让已经实现的链路恢复可用，建立可重复验收基线，不新增独立 Spark 作业能力。

### 工作项

1. 检查 WSL 的 Spark、Metastore、HDFS 进程与脱敏日志，确认停止原因；核对数据目录，禁止初始化覆盖现有仓库。
2. 在实施授权下按依赖顺序恢复服务，确认 relay 地址及数据源配置一致。
3. 从 metadata 容器实际访问路径验证连接，而不是仅在 WSL 内连接 localhost。
4. 使用真实平台身份执行 SELECT 1、元数据读取和已知小表查询。
5. 只在专用测试库/分区执行最小写入、结果校验、重复运行；不重跑全部造数脚本，不覆盖业务表。
6. 为运行状态增加“未知、探测中、可用、不可用、最近成功时间、脱敏失败原因”。区分连接探测与慢查询，不在每次打开页面时触发全库扫描。
7. 增加 Spark 依赖健康检查与环境恢复说明；开机自启作为明确配置项，不无条件接管用户系统启动策略。

### 验收

- 平台身份 → 网关 → metadata → relay → Spark 的真实查询成功，结果正确。
- 授权测试身份可查，未授权身份拒绝；失联时提示具体依赖，而非继续显示可用。
- 测试加工结果与独立校验一致；重跑不重复写入。
- 保留恢复步骤、探测记录和验证 SQL；复验只操作专用测试数据。

## 4. M1：安全与统一执行基础

### 目标

先让现有 SQL 任务具备安全、可追踪、并发可控的执行契约，再把 Spark 接到同一契约。

### 工作包 A：查询和身份边界

- 修复多行 SQL 禁止词漏检；依据实际 Hive/Spark 方言建立解析与拒绝策略，不以替换某个解析器就宣称绝对安全。
- 对未知、不支持结构采用明确拒绝，测试 CTE、注释、嵌套、写操作和危险函数。
- 查询账号与加工账号落实最小权限；数据库支持时启用只读事务，不能仅依赖 JDBC 标志。
- 统一最终用户/应用/项目/资源上下文。数据集、Agent、API 与控制台遵守同一执行处权限规则。
- 修复具体指标 ID 缺失、看板资源类型错误、依赖图未过滤等问题；验证字段权限、脱敏与查询结果缓存不能串用户。
- 服务间鉴权失败关闭；内部服务令牌不替代最终用户授权。

### 工作包 B：执行状态与恢复

- 建议建立 ExecutionAdapter 契约：validate、submit、status、logs、cancel、reconcile；异步提交返回受管句柄。
- 保留任务逻辑实例，另存每次 execution attempt，防止重跑覆盖审计证据。
- 数据库原子抢占；使用租约/心跳与 fencing token，旧执行者不能覆盖新执行者状态。
- 定义 queued、submitting、running、cancel_requested、cancelled、succeeded、failed、timed_out、unknown；对网络失联使用 unknown/reconciling 语义。
- 区分确定失败与提交结果未知。网络超时不能直接判定集群没收到任务，也不能盲目重提。
- 每次执行绑定任务发布版本、代码摘要、参数摘要和输入/输出分区。
- 只有可证明安全的任务允许自动重试；追加写和覆盖写分别定义幂等策略。

### 工作包 C：审批与交付门禁

- 提交审批冻结内容快照及摘要；修改后批准失效；发布与批准消费使用原子状态切换。
- 建立实际 HTTP 层鉴权测试、权限服务故障测试、真实数据库并发测试。
- 修正 Compose 镜像引用，绑定不可变提交版本；构建发布依赖 CI 成功，部署增加健康与最小业务验收。
- 数据库迁移采用兼容升级与恢复策略，不能把 Git 回退等同于数据回滚。

### 验收

- 并发提交同一业务实例，仅一个有效执行者获得执行权。
- 提交成功但响应丢失，不产生第二个作业；平台重启可恢复对原作业的追踪。
- 审批后修改内容不可沿用旧批准发布。
- 权限撤销、身份伪造、跨项目访问和字段越权测试通过。
- CI 能阻止上述回归进入发布，而非仅通过旧方法单测。

## 5. M2：独立 Spark 批作业最小完整版本

### 先做一次技术验证

核对真实集群目标、Spark/Java/Hadoop/Python 版本、资源上限、存储和身份机制。现有脚本引用 Spark 3.5.6，不应盲目按 latest 文档升级环境。

优先保留单一后端适配器：

- 有稳定 YARN 环境时，验证受管提交器或 Livy batch 接入；不因旧文档写过 YARN 可达就假定目前可用。
- 本机仅用于开发验证，可先使用受管本地提交器，但不得宣称多节点生产能力。
- 不同时实现 Livy、Standalone、YARN、Kubernetes 四套接入。适配器边界支持后续扩展即可。

Spark 官方的独立应用提交入口为 spark-submit；Livy 提供 batch 创建、状态、日志和删除接口，可作为候选控制面。必须验证版本兼容、身份、重启与幂等行为，不能只测试 POST 成功。

### 首版范围

1. 支持一种受管批作业，例如经审批的 PySpark 模板；JAR 类型可在同一协议下后续增加。
2. 维护计算环境、不可变制品、任务发布版本、执行尝试、真实运行句柄和事件记录。
3. 接入提交、状态跟踪、日志分页/游标、取消、超时、恢复、受控重试。
4. 保存平台实例 ID、attempt ID、远程 batch/submission ID、Spark application ID；不同 ID 不混用。
5. 前端提供任务定义、参数、资源配置、发布版本、运行记录、日志和取消入口。
6. 每次运行绑定制品摘要，禁止历史版本悄悄指向被覆盖的文件。
7. 日志隐藏凭据、限制大小并设保留策略；历史页面访问也执行权限校验。

### 必须同时交付的安全措施

PySpark/JAR 可以执行程序，SQL 守卫不能作为它们的沙箱。首版只接受审批过的受管制品，不向任意用户开放自由代码执行。

- 作业使用受限运行身份，不继承平台管理令牌和整份 .env。
- 资源参数白名单、CPU/内存/时限/并发上限、文件路径与制品来源校验。
- 使用结构化参数调用提交器，禁止拼接 shell 命令。
- 作业网络和存储访问限制在授权范围，防止绕过平台读取其他数据源。
- 控制面与日志 UI 不裸露到公网；集群选择相应认证、加密与访问控制。
- 取消必须确认远端工作已终止，不能只把数据库状态改成 cancelled。

### 验收用例

| 用例 | 必须满足 |
| --- | --- |
| 正常完成 | 真实 application ID、正确输出、日志与最终状态一致 |
| 参数/代码错误 | 可定位原因，无凭据泄露，错误不能记为成功 |
| 运行中取消 | 远端确认终止；结果是否部分提交有明确说明 |
| 提交响应丢失 | 可发现既有作业，不盲目重复提交 |
| 平台重启 | 能重连既有作业并继续追踪 |
| 作业进程失败 | 状态最终收敛，是否重试由任务策略控制 |
| 未授权用户 | 不能提交、取消或读取他人的受限日志 |
| 幂等重跑 | 测试分区结果正确，无重复追加 |

这一步验收后，才把“Spark 开发”从 comingSoon 改为可用。此时可以称为受控独立批作业管理，不应称为企业级多租户计算平台。

## 6. M3：Spark、数仓加工与治理统一闭环

### 工作项

- 同一 DAG 混合执行 SQL、Spark 和质量节点，按业务日期检查依赖。
- 定义跳过、失败阻断、人工豁免、补数范围、并发及重跑行为；不默认重跑所有下游。
- 建立任务 → 表/字段 → 模型/维度/指标 → 数据集/看板/API/Agent 的依赖关系。
- 关联代码版本、执行 ID、输入/输出分区与血缘，未知解析结果明确标注，不伪造完整血缘。
- 下线或不兼容变更前执行影响检查；阻断与豁免均有权限及审计。
- 全入口统一查询审计，修复表 ID 写入数据源 ID 的错误；明确用户拒绝、执行失败、审计失败的不同语义。
- 新版本数据先写隔离分区/暂存区，验证通过后按底层能力发布；不假定所有存储都有原子事务。

### 验收主线

订单接入 → ODS → Spark 清洗 DWD → 汇总 DWS/ADS → 质量门禁 → 指标审批发布 → 数据集/看板消费。

验收需证明坏数据不会进入新发布版本、旧版本可继续消费、失败可定位到任务与分区、下线前可识别影响消费者。

## 7. M4：真正开放受管数据服务

### 工作项

- 应用注册、负责人、申请审批、资源授权与环境隔离。
- API 资产绑定不可变查询定义/指标版本、参数 schema、响应契约、最大行数与超时。
- 默认开放参数化服务，不先开放任意 SQL。
- API key 仅一次展示；验证用不可逆存储，支持到期、轮换、吊销与短期过渡策略。
- 配额持久化；多副本部署前验证共享限流；按应用与服务计量，不使用可无限增长的路由字典。
- 记录调用量、错误、P95、可用性、调用链 ID；增加版本废弃通知。
- URL 的 /v1 是协议版本，与服务资产的发布版本分别管理。

### 验收

未经授权不能调用；撤销在约定时限生效；轮换不泄露旧密钥；并发实例不能绕过配额；相同 API 发布版本返回兼容契约；错误与资源消耗可追踪。

## 8. M5：语义计算与智能问数增强

### 工作项

- 多表 JOIN 校验关系基数、重复聚合、时间口径与权限传播；先做小范围受控模型。
- 派生/复合指标使用表达式 DAG，检查循环依赖、粒度、空值、除零与类型。
- 新版本试算比较旧版本，展示差异与影响，审批冻结口径。
- Agent 检索、工具执行、结果及缓存均继承用户数据权限。
- 引用真实指标版本和数据更新时间；不能把检索文本当成权限或操作指令。
- 建立固定问答评测集，覆盖正确口径、越权、无数据、歧义、多轮上下文与错误恢复。

### 验收

典型指标有独立计算基准；多表结果没有连接放大；Agent 不返回无权限资产；歧义时澄清而非编造；每次升级保留准确率与越权测试结果。

## 9. M6：按真实需求进入规模化与流式

不要把 Kubernetes 或 CDC 当成“企业级”的装饰性清单。先测量瓶颈和业务时效需求，再确定投入。

- 运行容量：排队时延、作业时长、失败率、CPU/内存、存储和元数据数据库连接池。
- 多副本：共享调度协调、租约、限流、撤权状态与日志；不只增加容器数量。
- 多租户：计算身份、网络、数据目录、凭据和成本配额隔离。
- 备份恢复：明确 RPO/RTO，并实际演练数据库、制品、仓库与元数据的一致恢复。
- 流式：确有实时需求后再做 CDC/Structured Streaming，补齐 checkpoint、迟到数据、Schema 演进、回放与端到端一致性。
- Kubernetes 迁移另设独立验收，不与首版 Spark 功能混合交付。

## 10. 每轮共同交付规则

1. 先确认现有用户改动，按明确范围实现，不顺手重构无关模块。
2. 每轮交付代码、迁移、API 契约、前端、负向测试、部署与恢复说明、运行验收记录。
3. 构建成功不等于运行验收通过，容器健康不等于外部计算链路可用。
4. 测试数据隔离；禁止清空现有数据库卷、重新格式化 HDFS 或覆盖仓库造数。
5. 无权限、超时、失联、并发、撤权和重启恢复都是验收内容，不是以后再补的异常分支。
6. 提交只包含本轮文件；GitHub 推送和实际部署按用户当轮授权执行。
7. 每轮先输出实际完成、证据、未完成与风险，再更新成熟度；不以页面完成率作为质量指标。

## 11. 推荐下一轮的实施范围

**先执行 M0，再实施 M1 中直接阻塞 Spark 的执行安全、原子抢占和身份契约，然后进入 M2。治理完善和数据服务开放不要变成无限推迟 Spark 的前置条件。**

建议拆成三个独立可验收交付：

- 交付 A：现有 Spark SQL 恢复 + 容器路径验收 + 状态真实性。
- 交付 B：统一执行契约 + 原子抢占 + 身份/SQL 防护 + 提交未知状态恢复。
- 交付 C：受管独立 Spark 批任务 + 应用 ID/日志/取消/恢复 + 完整界面。

工期应在 M0 环境恢复与 M2 集群技术验证后估算；当前没有足够证据承诺具体天数。每个交付以验收结果为进入下一步的条件。

## 12. 官方技术依据

- Spark 3.5.6 应用提交与部署模式：[Submitting Applications](https://spark.apache.org/docs/3.5.6/submitting-applications.html)。local 与集群模式含义、部署模式及制品提交方式以此核对。
- Spark 3.5.6 安全边界：[Spark Security](https://spark.apache.org/docs/3.5.6/security.html)。网络、RPC、UI 与不同集群管理器的安全配置不能省略。
- Livy 候选批作业控制接口：[Livy REST API](https://livy.incubator.apache.org/docs/latest/rest-api.html)。batch 创建、状态、日志及删除是接口能力，不等于 Aetheris 已完成接入。

以上是与当前脚本版本及候选接口相关的资料，不是对 3.5.6 当前安全维护状态的认证；上线前需另行核对发行版支持与安全公告。
